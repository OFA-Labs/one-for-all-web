# Local execution contract for future web integration

This documents the current API feature in the companion `one-for-all-api` repository. The web PR adds documentation only. It does not connect the public preview to a local machine or implement voice, models, signup or device pairing.

## Start the local feature

Follow `docs/local-execution/README.md` in the API repository. On Windows with Python 3.12, install the feature-specific pinned dependencies and run:

```powershell
python -m ofa_execution --test-pad
```

The launcher opens its own local control page and enables only the disposable OFA Test Pad. Other applications, files and browser origins require explicit local configuration. No model key, Gradium setup, public identity or cloud service is required.

## Trust and transport boundary

The local feature binds to `127.0.0.1` on a chosen/free port. Every `/api/` request requires its per-process local bearer credential. The launcher supplies that credential to its own page through a URL fragment; it is not a production user identity or a public-website pairing mechanism.

Do not put this credential into the Next.js bundle, public environment variables, browser logs, committed configuration or PR comments. The current API rejects foreign Origin/Host values and enables no broad CORS grant. A future hosted website must use a separately reviewed local connection/pairing design; it must not bypass those checks.

## Current endpoints

| Method | Path | Input / result |
|---|---|---|
| GET | `/api/capabilities` | Schema version, session ID, hand operations/availability, allowed app names, local control status |
| GET | `/api/tasks` | Current bounded in-memory task snapshots |
| GET | `/api/tasks/{task_id}` | Task state, frozen plan, observation, approval/question/handoff, effects and numbered events |
| POST | `/api/commands` | `{command_id,text,source}`; current typed deterministic commands |
| POST | `/api/tasks` | `{command_id,plan}`; structured multi-step execution |
| POST | `/api/tasks/{task_id}/decision` | `{command_id,approval_id,reading_hash,approve}` |
| POST | `/api/tasks/{task_id}/answer` | `{command_id,question_id,option_id}` |
| POST | `/api/tasks/{task_id}/control` | `{command_id,action,handoff_id?}` |
| POST | `/api/control` | Global `stop` or explicit `resume` for this local session |

Source of truth: `ofa_execution/contracts.py`, `api.py` and `engine.py`. Unknown request fields are rejected. IDs in the examples below are placeholders; reuse the same command ID when retrying the same request, and use IDs/hashes actually returned by the backend for cards and handoffs.

## Typed command and structured plan examples

```json
{
  "command_id": "<COMMAND_ID>",
  "text": "open OFA Test Pad",
  "source": "typed"
}
```

The grammar currently accepts `open <allowed app>`, `browse <allowed URL>` and `read file <allowed path>`. Unsupported language returns `UNSUPPORTED_COMMAND`; it is not passed to a hidden reasoning provider.

```json
{
  "command_id": "<COMMAND_ID>",
  "plan": {
    "schema_version": "ofa.execution.v1",
    "title": "Open and inspect the allowed test app",
    "source": "structured",
    "steps": [
      {"operation": "app.open", "target": {"app": "OFA Test Pad"}},
      {"operation": "window.observe", "target": {"app": "OFA Test Pad"}}
    ]
  }
}
```

The API returns `{task_id,session_id,state}`. Step IDs may be generated by the backend. Maximum 50 steps; one foreground task and up to three queued. A plan is copied/frozen on submission. Page/file observations cannot append instructions, sites or actions.

## Render actual state

Snapshot states include `queued`, `running`, `approval`, `question`, `handoff`, `paused`, `completed`, `failed`, `cancelled` and `unknown`. Show these actual signals instead of simulated workers or completion timers. Events contain sequence, task/step/session/hand/approval IDs and timestamps; snapshots also contain `last_sequence`.

- Show exact action and independent reading from the approval card. A decision sends the current card ID and reading hash. First decision wins; a changed reading rebuilds the card.
- Clarification uses an offered `option_id`; do not invent a structural target or click a neighbour.
- Human-only steps require explicit `continue` with the current `handoff_id`, then a fresh read. Continue is not a final-action approval.
- Controls are `pause`, `resume`, `cancel`, `stop` and `continue`. Stop suppresses future input and requires explicit resume. Existing effects are preserved.
- `unknown` is a real outcome. After a possibly dispatched action loses its reply, do not automatically resend it or display success.
- Current completion requires fresh Tier A readback. A successful tool return alone is insufficient.
- API execution errors use `{code,message,options}` with HTTP 409. Authentication is 401, foreign Origin/Host is 403, oversized requests are 413, and invalid request schemas are 422.

Tasks, approvals and history are volatile. A process restart changes the session and invalidates grants; the UI must not replay old tasks or cards. Inspect actual external state before a new request.

## Future adapters

Final voice transcripts can supply the same Command/Plan boundary. Speech-start must map to immediate hold/pause before transcription finishes. Task/question/approval/completion events can be consumed by the separately owned voice pipeline. Current approvals are tap-only; voice-code eligibility is future work.

Future reasoning providers implement `PlannerAdapter` and return a structured plan. They do not gain direct MCP, UIA, script, shell or approval access. A vision provider may consume an observation/frame later; unavailable screenshots/structural targets must remain explicit limitations now. Browser screenshots are currently unavailable until local masking is configured.

Public authentication, secure cross-device pairing, providers/BYOM UI, connector OAuth, Telegram/phone, persistent memory and cloud infrastructure stay outside this milestone. Tests of deterministic fixtures establish execution behaviour, not live AI reasoning or compatibility with every installed application.
